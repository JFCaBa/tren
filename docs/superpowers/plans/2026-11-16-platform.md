# Platform (UK) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Andén for Great Britain: open the app and see the next National Rail departures at the nearest station, with delays, cancellations and platform.

**Architecture:** A static `stations.json` (CRS + name + coordinates, built from open data) on GitHub Pages; a small Python API on the existing VPS behind nginx (`https://api.whatplatform.uk/departures/{CRS}`, 30 s cache per CRS, no access log) that calls Darwin with a key kept on the server; a Flutter app copied from Andén with the Spain-specific data layer replaced.

**Tech Stack:** Python 3.12 stdlib (pipeline + API, `unittest`), Docker Compose, nginx + certbot on the VPS (`ssh myairports`), Flutter/Dart (same versions as `tren/app`), GitHub Actions + Pages.

**Spec:** `docs/superpowers/specs/2026-11-16-platform-design.md` (moves to the `platform` repo in Task 1).

## Global Constraints

- **No code before Task 0 passes**: RDM account approved, platform agreement and Live Departure Board licence read with the user, subscription done, one real call recorded.
- Darwin key never in the app, the repo, the chat or CI logs. It lives only in `/opt/platform/.env` on the VPS (mode 600), written by the user.
- Free and ad-free; no accounts, analytics or data collection ("Data Not Collected"). nginx site with `access_log off`; the API never logs client IPs.
- Attribution to National Rail visible in the app (footer of the departures screen) and in store listings, with the exact wording the licence requires (recorded in Task 0).
- Domain `whatplatform.uk` (Cloudflare DNS, "DNS only" → 217.182.195.66): `whatplatform.uk`, `www`, `api`.
- App: British English, 24 h times, iOS + Android; provisional bundle id / applicationId `com.jfcaba.platform`; provisional name "What Platform".
- Refresh every 30 s only while the screen is in the foreground; on HTTP 429/503 wait 5 min before retrying, with a banner.
- Stale data: on a failed refresh keep the last board with a "Last updated HH:mm" banner; after 10 min without fresh data hide the services and show only the banner with "Retry".
- API contract (fixed here; the app depends only on this, never on Darwin's format):
  ```json
  {"crs":"KGX","name":"London Kings Cross","generatedAt":"2026-11-20T10:14:03Z",
   "nrccMessages":["Plain text, HTML stripped"],
   "attribution":"<exact text from the licence>",
   "services":[{"std":"10:15","etd":"On time","platform":"9","destination":"Cambridge",
                "via":"via Hitchin","operator":"Great Northern","cancelled":false,
                "delayReason":null,"cancelReason":null}]}
  ```
  `etd` ∈ {"On time", "HH:MM", "Delayed", "Cancelled", null}; `platform`, `via`, `operator`, `delayReason`, `cancelReason` may be null; services in Darwin's order. `generatedAt` is Darwin's own generation time (not the API's), so a stale cached answer is recognisable as stale.
- Times shown to the user ("Last updated HH:mm") are formatted in `Europe/London`, whatever the phone's time zone.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; validate each diff with the `consenso` skill before committing (user's CLAUDE.md), except docs-only commits.
- Store submission ("Submit for review" / "Enviar a revisión") only with explicit user confirmation in chat.

## Review Focus

1. Station with no departures in the window (late night, closed station) → API returns `services: []` (200), app shows "No departures in the next 2 hours", not an error. *(Task 3 test, Task 6 test)*
2. Darwin `nrccMessages` contain HTML (`<p>`, `<a href>`) → API strips tags and decodes entities; the app never renders HTML. *(Task 3 test)*
3. Split / multi-destination services (Darwin returns several destination locations) → `destination` is the names joined with " & ". *(Task 3 test)*
4. Darwin slow or down → API answers 502 with JSON within 10 s; nginx caches 502 for 5 s so a Darwin outage doesn't multiply calls. *(Task 3 test for timeout; Task 4 verification for nginx)*
5. Midnight crossover (`std` "23:58", `etd` "00:03") → the app shows the strings as given and keeps API order; it never parses times to sort or compute minutes. *(Task 6 test)*
